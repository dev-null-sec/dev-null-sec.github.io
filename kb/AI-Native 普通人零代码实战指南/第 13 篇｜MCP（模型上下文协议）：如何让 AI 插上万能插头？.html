第 13 篇｜MCP（模型上下文协议）：如何让 AI 插上万能插头？ ​

导读：
还记得我们在第 03 篇给 AI“装器官”、在第 11 篇拆解 Harness“四大支柱”时，反复提到的那个神秘插座吗？
为什么一个写代码的大脑，能突然跨软件去翻你的 Notion 笔记、查你的数据库、甚至自己点开浏览器替你做测试？
背后支撑这一切的核心协议，就是当前席卷整个 AI 工业界的 MCP（Model Context Protocol）。
这一篇，我们把前面埋下的伏笔彻底收网。而且最爽的是：你根本不需要手动去手写复杂的配置文件，现在的 AI 自己就能帮自己把插头稳稳插上！

一、 串联记忆：它就是 Harness 的“终极外设总线” ​

我们先做个快速回忆：

  • 在 第 03 篇，我们讲过大模型天生看不见实时世界，必须通过外挂雷达（如 Tavily）给它送情报；
  • 在 第 11 篇，我们把 Harness 拆成了规矩（Rules）、状态（Context）、战法（Skills）和万能插座（MCP/Tools）。

在过去，给 AI 装外部工具是一场折磨：
如果你想让 AI 连上 GitHub，得写一套专用插件；想让它连数据库，又得写一套私有通道。如果市面上有 5 种 Agent、100 款软件，全世界就得搞出 500 种互不兼容的接口。

MCP（Model Context Protocol，模型上下文协议）彻底终结了这种各自为战的混乱。
它由 Anthropic 开源并迅速成为全行业共识：不管你用的是 Cursor、Windsurf、Claude Code 还是各大桌面 Agent，大家都遵循同一套插座规格。

软件厂商只需把自家工具做成标准的 MCP Server（插头），你的 Agent 只要支持 MCP Client（插孔）。插头往插孔里一推，原本孤零零的模型瞬间就接入了真实世界的数据网络。

二、 普通人做项目，最值钱的三大 MCP 场景 ​

不用把所有的 MCP 都装一遍，只要拥有以下三个插头，你的 Agent 就从“键盘侠”蜕变为了“全能特种兵”：

场景 1：直连数据库（告别人肉传话） ​

  • 插上什么：PostgreSQL / SQLite / Supabase MCP。
  • 过去：你想让 AI 改一段业务查询，你得打开数据库客户端 ➔ 导出建表语句 ➔ 复制给 AI ➔ AI 猜一段 SQL ➔ 你再复制回数据库跑 ➔ 报错了再截图给它。
  • 现在：你直接在对话框里说：

    “看一下本地数据库里的 users 表，给新注册的用户加一个积分字段，并把默认值设为 100。”
    AI 顺着 MCP 探针直接潜入数据库，自己读取表结构、执行微调并反馈结果，人肉搬运这一步就全省了。

场景 2：直连 GitHub（一人拥有整个研发协同组） ​

  • 插上什么：GitHub MCP。
  • 实战体验：项目上线后，用户在 GitHub 上提了 Issue。你不需要去网页端逐字阅读。在本地告诉 Agent：

    “拉取我们仓库里编号为 #12 的 Issue，看用户反馈的报错，定位本地代码修好它，并自动发起一个 Pull Request。”
    Agent 顺着插头去读取 Issue 讨论、关联本地代码文件、完成修复，甚至直接把分支推上去发起 PR。

场景 3：唤起真实浏览器自动点点看（Playwright / Puppeteer MCP） ​

这是普通人最震撼的体验——把软件测试彻底交给 AI。

  • 插上什么：Playwright MCP（浏览器自动化驱动）。
  • 实战体验：写完前端网页，很多新手根本不知道各个按钮是不是真能点通。现在你只需要下达任务：

    “使用 Playwright MCP 打开本地 localhost:3000，模拟一个新用户完成注册：输入邮箱、输入密码、点击注册。截一张成功后的屏幕截图给我看；如果有报错，自己看控制台日志并改好代码。”

你下达命令 ──► Agent 触发 Playwright MCP ──► 电脑自动弹出一个浏览器！
                                                     │
                                                     ▼
                                        AI 像隐形人一样：
                                        自动把鼠标移过去、敲键盘、点击！
                                                     │
                                                     ▼
                              【发现按钮点不动】 ➔ AI 自己看红字报错
                              【自己回编辑器改代码】 ➔ 重新跑一遍浏览器直至通过！

有了这个插头，AI 不仅帮你搬砖，还兼任了你的专职质检员（QA）。

三、 告别手写 JSON：现在的 MCP 连配置都由 AI 代劳 ​

很多老教程还在一本正经地教大家：“打开隐藏文件夹，找到 config.json，小心翼翼地复制几行容易报错的大括号代码……”

千万别自己去受那个罪！在当下的生态中，给 AI 装插头是一句话的事。

现在的 Agent 工具链（包括 Cursor、Claude Code、各类桌面 Agent 客户端）早就支持了自动化挂载或一键市场：

                    【现代 MCP 极简接入流】
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
       【桌面客户端：点鼠标】                 【Agent 指令：一句话】
   进入 MCP 设置面板 / 插件市场          直接对 Agent 说：
   直接点击 [Install / Add]            “帮我给项目安装配置 GitHub MCP”
               │                               │
               └───────────────┬───────────────┘
                               ▼
        AI 自动下载服务、自动写入底层配置、自动测试连通性！
                               │
                               ▼
       弹窗提示：浏览器授权登录（OAuth），点一下即刻通电！
  • 如果你用终端/桌面 Agent：你甚至只需要敲一句 claude mcp add [服务名]，或者直接用自然语言告诉它：“我要连接我的本地 Postgres 数据库，帮我把配置配好。”它自己就会调取系统工具把环境搞定。
  • 你唯一需要做的动作：如果涉及 GitHub 或第三方账号，系统会弹出官方的安全授权网页，你像平常登录微信一样点一下“确认授权”，插头就接通了。

不用懂网络协议，不用敲代码，更不用手写 JSON。 你只需要告诉它：“去把那个插头插上”，剩下的脏活它自己搞定。

📝 结语与本篇自查（模块三完美收官） ​

  1. MCP 与我们在第 11 篇学到的“Harness（脚手架）”是什么关系？
    (MCP 是 Harness 里连接物理世界的“通用插座”，它让 Harness 不再局限于纯文本规则，而是能实时操控外部数据库、软件和网络。)
  2. 为什么说 Playwright MCP 是前端开发者的“解放双眼神器”？
    (因为它允许 AI 自己唤起真实浏览器，模拟人类点击输入并自主截屏诊断，把测试和修复在后台全部闭环。)
  3. 在当下想要使用一个新的 MCP 工具，需要自己手动学写底层的驱动或改写复杂的配置文件吗？
    (不需要。利用现代工具自带的插件市场、或者直接对 Agent 下达安装配置指令，AI 会自动完成环境配置，用户仅需完成账号授权。)
